## Implementation order

### Phase 1 — Component fixes (OpStateBadge, OpKpi delta)

**`OpStateBadge`** — add `aria-label` with human-readable state text; current label is already the text (e.g., "published") so screen readers get it, but color alone still matters in dense tables — keep existing text, add `role="status"`.

Actual gap: the `label ?? state` text is already readable; the ONLY gap is that the badge relies on color (green/red/yellow/purple) without an icon. Per spec: *"significado no solo por color: llevan icono + texto"*. Add a leading icon character per state (visually hidden label is redundant when text is already there, but icons help color-blind users). Use `aria-hidden` on the icon, text is already present.

**`OpKpi` delta** — ↑ and ↓ glyphs have no programmatic meaning beyond direction. Add `sr-only` span with "Sube" / "Baja" and make the arrow `aria-hidden`.

### Phase 2 — Table scope + caption (all dense operator tables)

Add `scope="col"` to every `<th>` in `<thead>` rows. Add `<caption className="sr-only">` to each table.

### Phase 3 — BulkRevokeList sticky bar a11y

The bar is missing:
- `role="region"` + `aria-label="Acciones en lote"` 
- `aria-live="polite"` on the count span

### Phase 4 — Axe e2e extension

Extend `e2e/public-smoke.spec.ts` to add:
- `/gob` (operator auth gate — but we can test the redirect/public facing; for authenticated routes, use the owner-auth fixture like `auth-bypass.spec.ts` does — the test will skip if not seeded)
- `/adoptar`, `/refugios`, `/casos`, `/libreta/compartir`, `/r/invite` (public surfaces)
- A new `e2e/a11y-operator.spec.ts` for authenticated operator routes using the owner fixture for accessible-but-guarded pages  

For operator routes that require `govt`/`admin` accounts (not seeded in test DB), we test the public-facing 302 redirect target — the redirected landing page must still be axe-clean.
